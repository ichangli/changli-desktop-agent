# 长离桌面助手 v0.1 产品需求

版本：0.1｜日期：2026-10-29｜状态：v0.1.0 预览版已开源并发布 Windows ZIP/便携 EXE，独立运行与云端发布验证通过。用户反馈真实 API 与此前建议检查通过。逐项验证证据与限制见 PLAN 与 VERIFICATION。

## 1. 产品目标

做一个供个人在 Windows 上使用的长离角色桌面助手：能自然地进行文字交流、保留对话、记住明确交代的事情，并完成少量真实的电脑操作。

首版成功的标准是“聊得像设定中的角色、重启后能续聊、记忆可管理、操作结果可信”。视频用于参考界面与交互，不作为功能已经实现或模型能力已经核实的证据。

目标环境为 Windows 10/11 x64；技术栈采用 Electron、Vue 3、TypeScript、SQLite。架构与开发步骤见 [PLAN.md](PLAN.md)。

## 2. 首版范围

### 2.1 包含的功能

- 长离头像、文字聊天、流式回复、停止生成、会话切换与本地保存。
- 一个选定的模型供应商接入；设置页可填写接口地址、模型和凭据，并检查连接。
- 用户明确要求保存的长期记忆，支持新增、查看、修改和删除。
- 两项系统工具：打开白名单应用、查询电脑状态。
- 工具执行状态与结果展示；按应用保存并撤销授权。
- 最小页面为聊天页、设置页；记忆和工具记录可采用简洁面板。
- Windows x64 独立发行文件、公开 GitHub 源码与按版本标签发布的流程；下载与手动更新说明。

### 2.2 后续再做的功能

语音输入与朗读、角色音色、Live2D/三维形象、桌宠动画、主动搭话、定时提醒、通用屏幕控制、任意 Shell、文件操作工具、MCP、向量检索、多智能体管理和跨设备同步均不进入 v0.1。

视频中的“任务”“智能体”等导航不要求首版全部复刻。首版只支持文字输入，不实现图片、音频或文件附件分析。

## 3. 主要使用场景

1. 打开助手，与长离聊几句；回复逐步显示，必要时可以停止。
2. 关闭应用，稍后重新打开，继续上一段对话。
3. 告诉她“记住，我更喜欢简短的技术回答”，之后查看、修正或删除这条记忆。
4. 点“添加应用”选择网易云音乐的 .exe，确认卡片名称和路径并允许启动；之后说“打开网易云音乐”，看到执行进度与真实结果。默认名称与习惯名称不同时可先修改名称。
5. 说“看看电脑状态”，得到当前 CPU、内存等读数；未支持的项目明确说明。
6. 网络或工具发生故障时，看到具体失败状态，而不是角色声称已经完成。

## 4. 功能需求

### 4.1 对话与角色（FR-01）

- 模型接口方案先固定一种，供应商与具体模型仍待选择；不承诺各家接口完全兼容。
- 连接设置为地址和模型输入框提供可选预设：`https://api.deepseek.com/chat/completions` 与 `deepseek-flash`，同时保留手填能力。“使用 DeepSeek 预设”一次填好模式、地址和模型，用户只需填写自己的密钥后保存；打开设置不覆盖已有配置，选择预设不自动保存或联网，保存时沿用原密钥处理规则。
- 支持发送消息、流式显示、停止生成、新建会话和选择已有会话。
- 正常回复、中断回复与失败请求应有可区分的状态，避免把半段回复显示为完成。
- 请求失败时提示可理解的原因并允许手动重试，不静默重复发送整轮请求。
- 运行时加载 [长离人设](../prompts/changli.md)；角色口吻与技术答复的清楚准确兼顾。
- 人设只约束应用中的角色表现；涉及电脑状态与操作结果时，以执行器返回值为准。

### 4.2 会话保存（FR-02）

- SQLite 保存会话与消息的内容、顺序、时间和状态；已落盘的记录在正常退出后保留。
- 应用意外关闭后，已保存的消息仍可读取；未完成请求显示为中断，不自动继续执行系统操作。
- 会话记录与长期记忆独立；新建聊天不等于删除长期记忆，删除记忆也不等于删除原聊天记录。
- 模型上下文可按明确规则截取或摘要；界面中的完整历史不因截取上下文而被删除。

### 4.3 明确记忆（FR-03）

- 保存入口为用户明确说“记住……”等指令，或在记忆面板中主动新增；首版不逐轮自动抽取用户事实。
- 每条记忆保留内容、来源、创建/更新时间以及类别；至少区分现实事实/偏好与角色互动约定。
- 角色扮演中的姿势、身份、关系、假设和临时情绪不能自动升级为现实事实。
- 来源或类别不清楚时先澄清；发生冲突时展示待更新内容，不静默覆盖旧记忆。
- 支持查看、新增、编辑、删除；操作后本地持久化，下次对话采用更新后的有效内容。
- 首版采用数量受限的简单召回，禁止每轮无限追加全部记忆；无需向量数据库。

### 4.4 打开白名单应用（FR-04）

- 用户点“添加应用”并选择实际启动 .exe；内部应用标识由后台生成，显示名称默认取程序文件名，不要求用户填写或查看内部标识。
- 用户可修改显示名称；改名保留原标识、目标及有效授权。重复选择同一目标复用已有记录，文件指纹相同时保留有效授权，文件变化则撤销旧授权。现有记录不迁移、不重建标识。
- 选择后展示名称与实际启动路径，用户明确确认授权后才允许启动，并能随时撤销。模型只提交内部应用标识，不能提供路径或命令字符串。
- 本地执行器检查应用是否存在、参数是否合法、当前授权是否有效，再决定能否启动。
- 首次配置授权后可允许该应用免重复确认；用户能查看和撤销授权，修改启动目标后应重新核验授权。
- 用户明确要求打开已授权应用时可以执行；目标不明确时先澄清，不自行选择其他应用替代。
- 禁止通过应用名称、参数或模型输出拼接任意 Shell 命令；不提供任意脚本执行入口。
- 启动成功依据操作系统执行结果报告；这不代表后续已经播放音乐或完成应用内部操作。

### 4.5 查询电脑状态（FR-05）

- 至少返回真实采样时间、CPU 使用率、内存总量/使用量/使用率；读数附单位。
- GPU 型号、利用率、显存、温度和 CPU 温度按本机能力提供；未支持、读取失败与数值为零要区分。
- 不编造温度、负载或后台进程活动；不将一次低负载读数直接解释为整机没有故障。
- 首版只按请求查询，不持续上传状态，不额外扫描文件、录屏或采集聊天以外的数据。

### 4.6 执行状态与中断（FR-06）

- 工具记录关联一次调用，区分等待授权、运行、成功、失败、取消和超时；状态来自执行器。
- 本地拒绝非法工具和参数，不把模型提供的文字当作成功证据。
- 支持超时、最大工具轮数以及停止后阻止后续调用；默认值在实现时配置并记录。
- 已发给系统的启动操作无法保证撤回；应报告实际状态，不虚称取消了已经发生的动作。
- 网络重试、重复回调或恢复会话不得自动再次执行同一次应用启动；结果不确定时说明不确定，不直接重放。

### 4.7 开源与版本交付（FR-07）

- 提供自带运行环境的 Windows x64 ZIP 和便携 EXE，用户无需安装 Node.js 或 npm。发行包必须包含运行时人设与必要资源。
- 在 GitHub 公开项目源码、依赖锁文件、MIT 代码许可证、第三方说明、使用方法和变更记录；不包含真实密钥、运行数据库、日志、聊天记录或私人素材。
- 项目是非官方同人应用，角色、游戏名称和第三方组件的权利单独说明，不将其声明为代码作者所有；不捆绑未获得分发许可的官方图片、音乐或音色。
- 每次推送版本标签时检查标签与程序版本一致，完成测试、构建、打包检查后发布对应文件和校验值；工作流不需要个人模型 API Key。
- 用户从 GitHub Releases 手动下载新版。正式版数据目录独立于程序文件与开发目录，正常更新不覆盖用户数据；不自动导入开发版或其他应用的私人数据。
- 按实际改动发布版本，不预设固定周/月发版日程。本版不包含应用内自动下载或热更新。

## 5. 数据与运行边界

- 桌面项目使用自己的配置、数据库和运行目录，不自动读取、改写或同步 QQ 机器人的生产配置、历史和记忆。
- 人设文件使用桌面项目独立草稿；运行时不依赖另一工程目录中的相对导入。
- 聊天与记忆保存在本机；若使用云端模型，构造请求所需的对话、相关记忆和工具结果会发送给对应服务商，不能宣传为完全离线。
- API Key 不写入仓库、前端静态文件或普通日志；实际凭据保存方案在接入时确定并验证。
- 日志仅记录排障所需信息，避免默认输出完整私人对话、凭据和请求头。
- 支持用户手动启动与退出；默认不添加开机自启，不改变已有 QQ 服务的运行状态。

## 6. 非功能要求

- 请求与工具运行时界面仍可响应；失败后能继续使用，不要求重启整个应用才能恢复。
- 本地保存失败应明显提示，不把保存失败的内容声称为已记住。
- 页面只调用受限本地接口；系统权限与参数校验由本地后台处理。
- 交付时写清已测试的 Windows 环境、模型接口、已知限制与启动方法，不把未验证平台写成测试通过。
- 首版不承诺固定完成周数、固定月费或所有电脑都支持全部传感器；根据实际验证补充。

## 9. 下一版本地开发：会话管理与备份（2026-10-30）

用户授权实现会话重命名、删除、历史搜索、聊天导出、聊天与记忆备份恢复；主题暂缓，未经后续明确指令不推送或发布 GitHub。此增量不改变 v0.1.0 发行包的能力说明。

- AC-22：会话可改名并重启保留，空会话自定名称不被首条消息覆盖；拒绝空名及超过 80 字符。
- AC-23：删除前明确二次确认；删除会话/消息/工具记录作为事务执行，保留明确记忆，删除最后会话后建立空会话；生成或工具执行时拒绝删除。
- AC-24：按会话名称和消息正文进行字面搜索，最多 100 段结果；可打开匹配会话并定位首条匹配消息，原有历史保留。
- AC-25：通过原生保存框将当前会话导出 Markdown，保留时间、角色、正文及回复状态；取消不写文件，失败有可理解提示。
- AC-26：通过原生保存框将会话和明确记忆备份为带版本标识的 JSON，不含凭据、设置、应用配置/授权、工具执行记录。
- AC-27：恢复前显示数量并要求确认，取消不写数据；新增副本而不覆盖原记录，重映射消息来源，未完成回复标中断，不执行历史工具。相同记忆跳过，已成功恢复的同一份内容不重复导入。
- AC-28：文件/结构/版本/唯一 ID/会话关联/字段类型与枚举检查；50 MiB、5000 段会话、100000 条消息、记忆总量 100 条限制；损坏/超额不部分导入，数据库错误事务回滚。文件路径仅来自原生对话框，页面无任意文件接口。

## 10. 下一版本地开发：桌面常驻（2026-10-30）

用户授权开始第二项桌面常驻体验；继续遵守暂不推送/发布 GitHub 的约束。主题、应用内更新、语音与全局快捷键不在本轮范围。

- AC-29：提供系统托盘及显示/隐藏/明确退出菜单；点击或双击图标唤回，最小化时恢复，再次启动通过单实例锁唤回已有窗口。
- AC-30：桌面设置提供关闭即退出（默认）或关闭到托盘，保存后重启保留；隐藏不停止当前生成与工具，每次手动启动显示主窗口，不新增自启。
- AC-31：托盘退出、界面二次确认退出与 app.quit 均能在托盘模式下真正结束进程；中断生成、取消未提交工具，等待现有任务收尾并关闭数据库，重启保留已落盘记录。
- AC-32：托盘创建失败时不隐藏窗口，设置和主动隐藏明确提示不可用，关闭仍可退出；注销/关机不被托盘偏好拦截。强制终止仍用既有数据库中断恢复，不能承诺系统强杀前完成异步收尾。
