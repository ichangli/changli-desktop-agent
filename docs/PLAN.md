## 最小架构

```text
Vue 界面：聊天 / 记忆 / 工具状态 / 设置
                 │ 受限 IPC
              preload 桥
                 │
Electron 本地后台
  ├─ 对话协调：流式事件、停止、上下文组装
  ├─ 模型适配：一个已选模型入口
  ├─ 持久化：SQLite 会话、明确记忆、执行记录
  └─ 工具执行器：应用白名单、授权、硬件采样
```

页面不直接持有 API Key 或系统执行入口。后台可以随实际负载把耗时采样等工作移到独立任务；第一版不提前拆成多个服务。

角色层由 `prompts/changli.md` 加上当前会话、适用的明确记忆和真实工具结果组成。工具定义、授权和执行状态由宿主程序提供；人设文本不能赋予系统权限。

## 数据设计原则

- 会话保存用户/助手消息、时间、生成状态；区分完成、停止和中断，重启后不假装仍在生成。
- 明确记忆保存内容、来源、创建/修改时间及适用范围；修改和删除后，后续模型请求使用最新有效记录。
- 工具执行记录关联请求和调用 ID，记录目标、授权、状态和结果，避免重试造成重复启动。
- 配置和运行数据放在项目专用的 Windows 用户数据位置，开发与正式数据分开；具体目录名在 M1 选定并记录。
- API Key 使用单独的本机配置/凭据存储方案，不放入角色 prompt、前端资源或普通聊天记录。
- 首版使用简单查询加载适用记忆，不加入向量检索；上下文裁剪需要保留必要的工具调用/结果配对。

- 用日常聊天、事实问答、记忆冲突和简短要求试聊独立人设，记录需要调整的地方。

对应验收：AC-06～AC-08。模型名称和试聊结果必须按实际记录。

### M3：两个电脑工具

状态：白名单选择/授权/撤销、真实 CPU/内存采样、执行记录、取消/超时和工具循环已实现。Codex 用本机 SSE 夹具和启动桩测试授权及防重；用户随后反馈此前建议的工具检查通过，未记录实际应用与逐项结果。GPU/温度未实现，明确标为不支持。

当前交互调整：点“添加应用”选择 .exe，由后台自动生成内部 ID 并从文件名带出名称；卡片可修改名称，改名保留 ID、目标和有效授权。用户确认名称与路径后仍需一次明确授权，并可撤销。同目标重复选择复用已有记录，相同指纹保留有效授权，文件变化撤销授权；原有 ID 不迁移。新交互已通过核心及 Electron 桌面回归。

限值：工具 10 秒、回复 90 秒、每回复最多 3 轮/6 次工具调用。启动不经 shell，不传额外参数；同一用户消息的同一 appId 持久化去重，跨手动重试或重启不重复启动。启动已提交后取消或超时返回不确定；恢复运行中的旧记录不重放。面板直接请求同样通过执行器。

- 应用启动：只需选择可执行目标，后台生成内部 app ID 与默认名称；确认授权后可启动，支持改名与撤销；未知目标明确拒绝。
- 硬件状态：返回真实 CPU、内存和采样时间；GPU、温度等仅在支持时返回。
- 完成工具参数校验、状态展示、超时、取消、调用次数上限和防重复执行。
- 由执行器返回结果后，再让角色根据结果继续回复。

对应验收：AC-09～AC-16。首版不包含打开应用后的任意点击、自动登录或自动播放歌曲。
